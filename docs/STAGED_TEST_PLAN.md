# Staged Validation Plan

This document separates source/host checks from target-device evidence. A green sandbox test, CI build, screenshot, or placeholder response does not prove a phone or laptop capability.

## Stage gates and current evidence

0. **Feasibility:** actual phone/laptop OS, hardware, restrictions, dependencies, unknowns and threat boundaries documented. Gate: facts and unknowns documented. **Status:** planning evidence exists; target models/OS are still unknown.
1. **Rootless runtime:** Linux host tests verify non-root refusal, private-home modes, exclusive ownership, storage admission, liveness/readiness, durable jobs and restart behavior. Added cases cover duplicate-key JSON rejection, rejection of home-itself as the state path without chmod, nonzero Stop status for unrelated live PIDs, concurrent duplicate keys, migration tampering, corrupt-header preservation, SQLite page corruption, and symlink/traversal refusal before mutation. **Status:** 20 sandbox integration tests pass; actual Termux install/start, Android storage/build behavior and phone persistence remain unverified.
2. **Android supervisor:** source/CI must verify manifest declaration, visible notification, Termux permission/opt-in behavior, fixed start/stop path, and an APK build. Target device matrix must cover lock/off screen, background, battery saver, Doze, network transition, low battery, thermal warning, memory pressure, process death, reboot, update, force-stop and manual restart. **Status:** hosted CI passed all eight Java/JUnit tests and assembled/uploaded a debug APK. Local Gradle execution stops before compilation because Android SDK/`ANDROID_HOME` is absent. Phone gate remains open. Termux permission is manually granted in PocketCloud app settings. Force-stop limitation must be honest.
3. **Resource protection:** inject/observe battery/thermal/memory signal availability and provenance; verify optional work yields safely, explains pause, and resumes only after hysteresis/dwell policy. **Status:** not implemented. Gate: no oscillation or user-impacting work.
4. **Cloud core/storage:** host migration, transition, quota, restart and corruption-injection checks. Still required: backup/actual restore, power-loss injection, disk-full and target-filesystem recovery. **Status:** host checks pass; backup/restore and real filesystem gates open.
5. **Secure pairing:** verify exact transcript, TLS SPKI pin/hostname verification, expiry, single-use replay rejection, invalid key/signature rejection and dual explicit consent. Then test on the same LAN with a real phone and actual Windows laptop; add revocation, rotation, key recovery and security review. **Status:** Android client and laptop bootstrap source are implemented; 17 laptop-host tests pass on Linux, including bounded/private sanitized audit-history checks. The previous 16-test baseline passed hosted Windows CI; current audit additions await a new hosted run. Android unit tests/build also passed in earlier hosted CI; no physical endpoint validation or independent security assessment is complete.
6. **Windows worker:** runtime OS/Python/GPU/driver/CUDA/resource/sleep probes, approved-handler dispatch, timeout, result persistence and graceful shutdown. **Status:** not implemented. Hosted Windows CI is not the user's laptop.
7. **Distributed execution:** disconnect/reconnect, worker restart, lease expiry, stale epochs, at-least-once retry, idempotent duplicate protection, result buffer and ambiguous-outcome quarantine. **Status:** future stage.
8. **Networking:** same-LAN direct without external service, network transition, offline queue, and honest unavailable-path UI. **Status:** pairing bootstrap alone is not authenticated job networking.
9. **Dashboard:** each visible control maps to a real API; inject API errors and verify safe presentation. **Status:** not implemented.
10. **Hardening:** dependency, input, security and regression tests; replay/revocation, fuzz, DB/storage failure. **Status:** 20 runtime tests and 17 pairing-host tests pass on Linux, including injected database/store corruption, duplicate-key rejection, home-path/ownership edge cases, bounded sanitized pairing audit records, path traversal/symlink cases, concurrency, Unicode names and stalled TLS clients. Security review/fuzz and target security tests remain.
11. **Release:** reproducible install/setup/recovery/uninstall, backup/restore, versioning/release notes, full phone-laptop proof, and 1/6/12-hour then 24-hour soak reports. **Status:** the prior revision passed all five hosted CI jobs, and a 15-minute Linux host soak completed 180 checks with zero failures. The latest hardening changes await a fresh hosted run; longer soaks and real phone/laptop proof remain open.

## Evidence records

For each run capture software revision, exact device/OS/build, setup steps, input conditions, timestamps, logs with secrets redacted, actual outcome, deviations, and recovery result. Distinguish sandbox tests, CI, phone and Windows results. Never substitute a planned test or synthetic signal for real-device evidence.
