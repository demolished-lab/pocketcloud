# Termux Stage 1 setup

This script is a rootless shell launcher, not an Android supervisor or uptime guarantee. It starts PocketCloud on loopback and requires the user to launch it. It does not set up a foreground service, boot receiver, Termux:Boot, battery-optimization exemption, or `RUN_COMMAND` integration.

From a trusted Termux installation, install Python 3.11 or later. In the checked-out repository, create a virtual environment and install the pinned package set with `python -m pip install -r requirements.lock`, then run `./scripts/termux/run.sh`. Keep the checkout and SQLite data in local app-private Termux storage. The database defaults to `~/.local/share/pocketcloud/pocketcloud.sqlite3`; `POCKETCLOUD_DATA_DIR` may select another private directory only under the current user's home. Paths outside that home are rejected. Use local device storage, not shared/external storage or a network-mounted directory; the runtime cannot reliably identify every possible filesystem/mount type. The default port is 8765; `POCKETCLOUD_PORT` must be 1024–65535.

The process refuses root, verifies ownership and private POSIX permissions for its data directory, database, and runtime lock, and acquires an exclusive per-data-directory lock before migration or recovery. A second instance using the same data directory exits instead of reclassifying live jobs. The service binds only to `127.0.0.1`; it does not accept LAN peers in Stage 1.

SQLite uses WAL, foreign keys, a 10-second busy timeout, synchronous FULL, and a page-count limit derived from the configured database ceiling. New job admission is serialized through the current bounded handler lifecycle; the preflight includes the database and WAL/SHM sidecars plus a conservative per-job write estimate. `POCKETCLOUD_MAX_DATABASE_BYTES` defaults to 64 MiB and `POCKETCLOUD_MIN_FREE_BYTES` defaults to 8 MiB. Set either value in the environment to adjust. New jobs are rejected before persistence when checks fail; no automatic job deletion or pruning is performed. The free-space check is point-in-time, so other applications can consume disk afterward. These controls do not replace backups, which are not implemented in Stage 1.

Use `GET http://127.0.0.1:8765/livez` for process liveness and `/readyz` for database readiness. Stop with Ctrl-C. On a genuine process restart, unfinished jobs are marked `needs_reconciliation`; they are not automatically replayed. Stage 1 has no authenticated dashboard and must not be exposed beyond the local device.
